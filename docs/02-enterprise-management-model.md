# 02 企业管理模型

## 1. 管理闭环

平台采用“战略—组织—执行—反馈—决策—学习”闭环，而不是把通讯录、审批、任务和知识作为互不相关的模块。

```text
战略主题 → 目标/指标 → 责任与资源 → 项目/流程 → 执行事件
  ↑                                              ↓
复盘与知识 ← 绩效与能力 ← 决策与调整 ← 风险与经营反馈
```

## 2. 战略与目标

- `MR-001` 战略主题定义企业希望发生的结构性变化。
- `MR-002` OKR 用于变化性目标，KPI 用于稳定经营，两者不得混为同一评分机制。
- `MR-003` 每个目标必须包含 Owner、周期、度量方式、基线、目标值、数据来源和检查频率。
- `MR-004` 目标通过项目、关键结果或例行流程承接，禁止只写口号。
- `MR-005` 目标状态由证据驱动，Agent 可以建议状态但不能自行签署正式状态。

目标状态：`draft → proposed → active → at_risk → achieved|missed|cancelled → reviewed`。

## 3. 组织与责任

平台同时维护三种组织结构：

1. 法定/行政组织：部门、岗位、汇报线。
2. 项目组织：跨部门虚拟团队。
3. 治理组织：委员会、审批组、值班组。

- `MR-006` 所有重要对象必须有唯一 Accountable Owner。
- `MR-007` 使用 RACI 表达执行、负责、咨询、知会关系。
- `MR-008` 授权必须包含对象范围、操作、有效期和可否转授权。
- `MR-009` 离职、转岗和组织调整必须触发权限回收与待办移交。
- `MR-010` 人员负荷仅用于容量规划，不直接作为绩效结论。

实现约束：组织异动以 `OrganizationChangeCase` 为唯一执行入口。转岗会重新计算角色和委托；离职还必须在同一事务内完成开放责任移交、成员关系结束、角色到期、委托撤销、设备撤销和外部身份撤销。只修改通讯录状态不构成完成。

## 4. 项目组合与项目

```text
Portfolio
└── Program / Project
    ├── ObjectiveLink
    ├── Milestone
    ├── WorkPackage / Task
    ├── Dependency
    ├── Risk / Issue
    ├── Decision / Change
    ├── ResourceAllocation
    └── Review
```

- `MR-011` 项目立项必须关联目标、业务价值、Owner、资源、期限和验收标准。
- `MR-012` 风险是可能发生的事件，问题是已经发生的事件，两者状态机分离。
- `MR-013` 里程碑偏差、关键依赖阻塞和预算偏差自动进入管理关注队列。
- `MR-014` 变更必须记录原基线、原因、影响、批准人和新基线。
- `MR-015` 项目关闭前必须完成交付验收、未结事项移交和复盘。

实现约束：项目的业务价值、资源计划和验收标准属于必填基线。任何范围、进度、预算、资源或质量变更都生成独立变更单；应用后生成绑定项目版本且限时有效的补偿计划。结项由数据库 Gate 强制校验评审状态，审批与项目完成必须处于同一事务。

管理关注队列只收集越过阈值的例外，当前覆盖里程碑逾期/风险、关键任务阻塞、高暴露风险、行动项逾期和预算超支，并以来源对象和原因码全局去重。

## 5. 流程与审批

流程实例包含触发条件、表单快照、节点、参与者、SLA、决定和审计链。

- `MR-016` 审批权来自岗位/策略，不来自 UI 中是否出现按钮。
- `MR-017` 同一人提出和最终批准高风险事项时必须触发职责分离检查。
- `MR-018` AI 预审只产生建议和证据，不改变正式审批状态。
- `MR-019` 撤回、驳回、加签、委托、转交和超时升级必须是显式状态迁移。
- `MR-020` 流程规则变更只影响新实例；运行中的实例保留发布时版本。

## 6. 会议、决策与行动

- `MR-021` 会议不是知识对象的终点，必须区分讨论、结论、决定和行动项。
- `MR-022` 决策记录包含议题、备选方案、依据、决定人、影响范围和复审日期。
- `MR-023` 行动项必须有责任人、期限、验收标准和来源决策。
- `MR-024` 决策被替代时保留历史，并建立 supersedes 关系。
- `MR-025` Agent 生成的纪要必须由参会人确认后成为正式记录。

## 7. 绩效与人才

- `MR-026` 绩效事实来源于目标、项目贡献、职责履行和明确反馈，不使用监控式代理指标。
- `MR-027` AI 可整理证据和识别缺口，不可独立打分、排序或作出雇佣决定。
- `MR-028` 绩效结论、人才标签和敏感反馈采用更严格的数据范围和保留策略。
- `MR-029` 1:1 记录默认仅双方可见，未经授权不得进入通用 RAG。
- `MR-030` 管理者必须能看到 AI 建议所使用和未使用的数据范围。

## 8. 管理节奏

| 节奏 | 系统产物 | Agent 支持 |
|---|---|---|
| 每日 | 个人重点、风险变化、阻塞 | 晨报、提醒合并、待办排序 |
| 每周 | 项目周报、团队负荷、行动项 | 状态草拟、异常解释、会议准备 |
| 每月 | KPI、预算、项目组合 | 趋势分析、资源冲突、经营材料 |
| 每季度 | OKR、人才、策略调整 | 目标复盘、贡献证据、情景分析 |
| 年度 | 战略、预算、组织能力 | 历史洞察、能力缺口、方案草拟 |

## 9. 事实、推断和决定

系统中的信息分为：

- `fact`：来自权威系统或人工确认的事实。
- `observation`：尚未确认的外部事件或内容。
- `inference`：Agent 根据证据作出的推断，必须带置信度和引用。
- `proposal`：待人工确认的方案或操作草案。
- `decision`：有权限的人作出的正式决定。
- `execution`：已经调用工具或改变业务状态的结果。

任何 UI、API 和审计记录都不得混淆这些类型。

## 10. 管理智能中枢一期

M12 将管理节奏、指标语义、项目组合情景、企业事项和 AI 质量治理作为同一管理闭环，而不是五个孤立菜单。详细对象、状态机和 `MR-031` 至 `MR-045` 见 [17 管理智能中枢](./17-management-intelligence-web-wecom.md)。网页承担配置、比较、证据和审计；企业微信仅承担提醒、接单、确认和 Deep Link，所有结果回写同一权威对象。
