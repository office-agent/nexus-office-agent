# 12 SLO、监控、备份与应急运行手册

## 1. 服务目标与告警

| 信号 | SLO/目标 | 告警建议 |
|---|---:|---|
| Web API 可用性 | 月度 ≥ 99.9% | 5 分钟 burn rate > 14.4 或 1 小时 > 6 时分页 |
| 普通读取 P95 | < 500ms | 连续 15 分钟超标告警 |
| 普通写入 P95 | < 800ms | 连续 15 分钟超标告警 |
| Webhook ACK P95 | < 500ms | 5 分钟超标并检查平台超时窗口 |
| Agent 首 token P95 | < 4s | 15 分钟超标，切换降级事实包 |
| 常规事件最终一致 | < 60s | Outbox/Inbox 最老年龄 > 60s 告警 |
| 必需 Worker 心跳 | 间隔 < 15s，过期阈值 < 45s | 任一 inbox/agent/outbox 角色无兼容心跳则摘除 Web readiness 并告警 |
| 死信与未知结果 | 正常窗口新增为 0 | 任一新增立即建立人工核对任务 |
| 审计完整率 | 100% | 任一高风险动作缺审计立即 P1 |
| 备份恢复 | RPO ≤ 15min，RTO ≤ 2h | 最近成功备份 > 20min 或校验失败立即告警 |

所有用户请求、AgentRun、ToolCall、InboundEvent、WorkflowInstance 和外部 API 共享 `trace_id`。应用以结构化 JSON 记录错误事件并输出进程诊断计数/时长；生产聚合以 OTLP 后端为准。日志字段会屏蔽 Authorization、Cookie、Secret、Token、密码、完整消息正文和敏感 Prompt。

仪表盘至少分为：入口/API、PostgreSQL、Inbox/Agent Job/Outbox 队列、Worker 租约与公平度、三平台连接器、Agent/模型、权限拒绝与高风险确认、备份/恢复。OTLP 只有在导出器已初始化且有发送回执时才可声明可用；环境变量存在不是运行证据。告警必须绑定负责人、升级路径、Runbook URL 和静默规则，禁止无人接收告警。

## 2. 备份与恢复

`npm run ops:backup` 调用 `pg_dump --format=custom`，从受管 Secret broker 按 `BACKUP_ENCRYPTION_KEY_REF` 取得 32 字节密钥，使用 AES-256-GCM 加密，原子写入加密制品和含 SHA-256、IV、认证标签的 manifest。`BACKUP_TARGET_URI` 当前支持 `file://` 挂载；生产挂载必须由跨可用区、版本化、对象锁/不可变策略保护。

恢复先在隔离环境做只读验证：

```bash
npm run ops:restore -- --manifest=/backup/nexus-....manifest.json --dry-run
```

输出会给出一次性的确认短语。真正恢复使用独立 `RESTORE_DATABASE_URL`，并显式设置同一确认短语后执行；工具校验 SHA-256 和 GCM 标签，再调用 `pg_restore --clean --if-exists`。恢复是破坏性操作，必须由事件指挥官与数据 Owner 双人批准，目标实例在执行前再次核对，禁止直接对不明生产地址运行。

每月至少恢复一个最新备份到隔离实例，执行迁移版本核对、租户行数抽样、RLS、安全旅程和审计完整性检查并记录实际 RPO/RTO。季度进行区域级恢复演练。

## 3. 发布回滚与补偿

应用镜像可回滚到上一已验证版本，但数据库不做破坏性向后迁移。若发布失败：停止新流量 → 保留证据 → 回滚兼容镜像 → 执行已评审的前向补偿迁移/重放 Outbox → 校验业务状态和审计 → 恢复流量。任何涉及已发送消息、审批或 Agent 工具副作用的回滚都必须走补偿动作，不能只改数据库。

## 4. 密钥轮换演练

- 会话：配置 `SESSION_SECRET_PREVIOUS` → 发布新 `SESSION_SECRET` → 验证新旧会话 → 等待最长 TTL → 清除旧值 → 验证旧会话失效。
- 连接器：在 Secret broker 创建新版本 → 平台侧保留供应商允许的短暂双密钥窗口 → 移动 `current` 引用 → 60 秒缓存期后验证签名与发送 → 吊销旧版本。
- 备份：新建加密密钥版本，只用于新备份；旧密钥按保留期只读保存，抽样验证新旧备份均可恢复后再按策略销毁。
- OIDC client secret 与 Secret broker bootstrap token：先增加新值、验证、切换，再撤旧；全程不得写入工单正文或聊天。

## 5. 事故响应

| 级别 | 例子 | 首次响应 | 处置 |
|---|---|---:|---|
| P0 | 跨租户泄露、密钥泄露、错误高风险执行 | 5 分钟 | 立即隔离、冻结写入/密钥、通知安全与管理层 |
| P1 | 核心 API 大面积不可用、审计缺口、RPO 风险 | 15 分钟 | 启动指挥、降级、回滚/恢复 |
| P2 | 单连接器故障、性能持续退化 | 30 分钟 | 切网页/异步队列，修复并补发 |

事件指挥官统一时间线和决策；技术负责人定位与恢复；安全负责人保全证据；业务负责人决定降级和通知范围；记录员只记必要且脱敏的信息。恢复后 48 小时内完成无责复盘，行动项必须有 Owner、期限、验收证据。

## 6. 降级策略

模型不可用时返回权限过滤后的事实包和引用，不执行工具；事故中可设置 `NEXUS_MODEL_MODE=disabled` 主动熔断模型，生产 readiness 会随即摘除实例，验证降级后再恢复。单平台不可用时保留网页事实源并排队通知；Secret manager 不可用时不回退到环境内联密钥；数据库不可用或必需 Worker 心跳过期时 readiness 下线实例且禁止内存仓储接管生产事实；重复事件依赖 Inbox/Agent Job/Outbox 原子租约与幂等因果键消除副作用。结果未知的工作项停止自动重试并进入人工核对。
