# 13 企业试点与变更管理手册

## 1. 试点目标

试点不是“让大家体验 AI”，而是验证一套管理制度能否被系统稳定承载。建议选 20～50 人、一个清晰业务负责人、两个跨职能项目和一个主要协作平台，连续运行四周。至少完成两个真实闭环：

1. 目标/指标偏离 → 项目风险 → 管理决定 → 行动项 → 证据 → 复盘。
2. 会议/知识输入 → Agent 只读准备 → 人工确认 → 决定/行动沉淀 → 负责人完成。

试点不把员工排名、雇佣建议、1:1 内容、私聊内容或监控式代理指标纳入范围。

## 2. 角色与治理

| 角色 | 责任 |
|---|---|
| 业务 Sponsor | 定义经营目标、处理跨部门阻塞、决定扩大/停止试点 |
| 试点 Owner | 每日运营、培训、反馈分流和验收证据 |
| 管理者 | 确认目标、风险、决定和行动，不把 Agent 建议当正式结论 |
| 一线成员 | 更新事实与证据，反馈流程摩擦，不承担模型校正责任 |
| IT/安全 | SSO、权限、连接器、日志、事故与数据保留 |
| 产品/实施 | 配置管理节奏、观察采纳、修复缺陷并维护决策日志 |

上线前完成数据分类、账号/组织同步、最小权限、渠道范围、通知静默时段、Agent L0～L3 边界、R3 确认人、应急联系人和退出方案。所有参与者知道 AI 输出可能错误，正式审批、绩效与高风险动作由人负责。

## 3. 四周节奏

- 第 0 周：基线访谈，记录现有会议时长、行动遗漏、风险发现提前量、跨系统重复录入和权限痛点；完成 SSO/平台真实 E2E。
- 第 1 周：只读与低风险建议，日站会 15 分钟，集中修复身份、权限、通知和数据口径。
- 第 2 周：启用 R3 提案确认，运行第一个管理闭环；每日核对审计和副作用。
- 第 3 周：运行第二个闭环和一次连接器/模型降级演练；观察管理行为而非点击量。
- 第 4 周：复盘成效、风险和未解决问题，由 Sponsor 决定扩大、延长或退出。

第 0 周接入顺序不得省略：管理员身份与主体映射 → OIDC Discovery/JWKS 预检 → 平台连接与外部企业绑定 → 回调密钥/令牌/身份 API 预检 → 测试收件人二次核对 → 生成方案 → 人工确认发送 → 平台侧回执核对。任一步为 `blocked`、`failed` 或 `unknown` 都不得进入下一步。

## 4. 采纳与反馈

反馈按四类分流：业务规则错误、权限/安全问题、模型质量、体验摩擦。P0/P1 进入事故流程；业务规则由流程 Owner 决策；模型问题必须带脱敏输入类别、期望行为、实际行为、引用和 trace ID，禁止复制生产 Secret 或完整敏感正文。

每周看板同时展示：管理闭环完成率、逾期行动、风险提前发现时间、人工确认撤回率、引用正确率、权限拒绝、重复副作用、连接器送达、API/Agent 延迟和用户主动反馈。不得用在线时长、键鼠活动或消息数量评价员工。

## 5. 退出与扩大条件

扩大条件：两个真实闭环完成且有审计 ID；无数据事故；跨租户/越权测试通过；关键结论引用可核验；普通读写和 Agent 延迟达标；备份恢复、回滚补偿和密钥轮换演练完成；管理者和一线成员分别确认流程可用。

立即暂停条件：疑似跨租户泄露、未确认的 R3/R4 副作用、审计缺口、无法撤权、错误人才结论进入正式决策。退出时导出必要业务事实与审计，撤平台应用权限和主体映射，停止通知和 Worker，按保留策略处理数据。

试点证据包包括：范围与人员、基线、培训签到、两个闭环对象 ID/审计 ID、异常和修复、性能报告、恢复/轮换记录、周度反馈、Sponsor 决策。没有真实团队和真实授权时，A-009 必须保持未通过。
