# 05 Agent 平台设计

## 1. Agent 定位

Agent 是受企业身份、业务规则和审计约束的工作协作者，不是具有超级管理员权限的自主机器人。

Agent 的核心输出类型：

- answer：带引用回答。
- insight：事实基础上的观察或风险判断。
- draft：周报、纪要、审批意见或方案草稿。
- proposal：包含预期影响的待确认动作。
- execution：经策略检查和确认后产生的执行结果。

## 2. 运行管线

```text
输入
→ 身份/租户解析
→ 权限过滤上下文
→ 声明式 Skill/Tool 目录
→ 模型原生理解与工具选择
→ 策略判定
→ 人工确认（按需）
→ 幂等执行
→ 结果验证
→ 审计与评测
```

业务意图不由服务端关键词、正则或固定语言路由。模型同时看到经过权限过滤的上下文、Skill 使用说明和可用 Tool JSON Schema，自主决定回答或调用工具。确定性代码只负责 Prompt Injection 边界、Schema 校验、权限/渠道/风险重验、人工确认、版本控制、幂等、超时和证据门禁。完整实现见 [18 工作指挥中枢](./18-work-command-center.md)。

## 3. 运行对象

AgentRun 保存：

- 用户、租户、入口渠道和会话。
- Agent/Profile/Prompt/Policy/Model 版本。
- 用户意图和风险等级。
- 上下文来源 ID，不保存无必要的全文副本。
- 模型使用量、延迟和成本。
- 工具计划、确认、执行和验证结果。
- 最终状态与评测标签。

## 4. 角色配置

角色 Agent 共享同一编排器，只配置目标、工具、上下文和政策：

| Agent | 主要上下文 | 工具 | 默认自治级别 |
|---|---|---|---|
| 员工助理 | 个人待办、日程、授权项目 | 搜索、草拟、创建个人草稿 | L2 |
| 经理助理 | 团队目标、项目、风险、容量 | 分析、周报、任务提案 | L2/L3 |
| PMO | 项目组合、里程碑、依赖 | 风险分析、状态提案、提醒 | L2/L3 |
| 高管助理 | 目标、指标、项目组合、决策 | 经营材料、情景分析 | L2 |
| 审批助理 | 表单、制度、预算、案例 | 材料检查、意见草拟 | L2 |
| 会议助理 | 议程、参会人、文档、转写 | 纪要、决策和行动项草拟 | L2 |
| 知识助理 | 权限过滤知识 | 检索、引用、比较版本 | L1 |
| 合规助理 | 策略、审计、异常事件 | 风险提示、调查草稿 | L1/L2 |

## 5. 自治等级

- `L0` 只读检索。
- `L1` 分析建议。
- `L2` 生成草稿或提案。
- `L3` 人工确认后执行。
- `L4` 在预批准策略、限额和可撤销范围内自动执行。

首期只支持 L0～L3。L4 必须在后续版本经过场景级安全评审。

## 6. 工具网关

Skill 是供模型读取的声明式认知与工作方法；Tool 是唯一可产生业务副作用的受控接口。Skill 不内嵌 Python 路由，不可以绕开 Tool Registry 写入数据。

每个工具声明：

```text
tool_id / version
input_schema / output_schema
required_permissions
risk_level
confirmation_policy
idempotency_strategy
timeout / retry_budget
compensation_tool
data_classification
allowed_channels
```

工具风险：

- R0：纯计算，不接触企业数据。
- R1：授权范围内只读。
- R2：可逆个人写操作。
- R3：影响其他人、项目或流程的写操作。
- R4：不可逆、财务、人事、权限或外发敏感操作。

R3 必须确认；R4 必须强确认并校验职责分离，首期可直接禁止部分 R4。

## 7. 上下文构建

- 先确定用户、租户、业务对象和时间范围，再检索。
- 使用最小必要上下文，不把整个企业知识库放入 Prompt。
- 引用记录 object_id、version、片段定位、数据分类和检索时间。
- 检索前执行 ACL，生成前再次过滤。
- 过期、草稿、被替代和 Agent 生成内容必须带状态。
- Prompt 中把外部文档内容标记为不可信数据，禁止其中指令改变系统行为。

## 8. 确认协议

确认卡必须展示：

- 将执行什么。
- 影响哪些人和对象。
- 使用哪个身份和工具。
- 是否可撤销。
- 关键参数和差异预览。
- 依据和不确定性。
- 确认有效期。

确认绑定 proposal_hash；任何参数、策略或权限变化后原确认失效。确认成功只表示“已授权并排队”，API 返回持久化任务引用，不得在确认请求线程中执行工具。Agent Worker 领用任务后再次读取当前身份、权限、策略和对象版本；状态机、未知结果与恢复规则见 [持久化执行设计](./16-durable-runtime.md)。

## 9. 记忆

- 会话记忆：当前对话，短期且可清除。
- 工作记忆：当前任务计划和中间状态，任务结束后归档摘要。
- 用户偏好：用户明确确认的格式、提醒和工作习惯。
- 企业知识：正式文档、业务对象和决策，不等同于模型记忆。

禁止将敏感聊天自动提炼为长期偏好；用户可查看和删除个人偏好。

## 10. 模型路由

路由考虑：数据等级、能力、延迟、成本、供应商可用性和租户策略。模型必须可配置，不在代码中硬编码单一供应商。

高敏感数据可配置为仅允许私有模型或关闭生成；模型失败时降级为搜索、模板或人工流程，不能静默换到不允许的供应商。

## 11. Agent 评测

离线评测：

- 权限与数据泄露测试。
- 引用正确性和可验证性。
- 风险分类和确认触发。
- 工具参数生成和拒绝行为。
- Prompt Injection 与越权请求。

在线指标：

- 任务成功率、工具成功率、确认率、撤销率。
- 引用完整率、用户纠错率、人工接管率。
- 延迟、成本和模型错误。
- 未确认执行、越权读取和敏感泄露必须为零容忍指标。

## 12. 失败处理

- 模型输出不能解析：不执行工具，返回可恢复错误。
- 策略服务不可用：失败关闭，禁止写操作。
- 外部平台超时：能证明未执行且满足幂等策略时才进入重试；无法证明时进入 `unknown` 并交人工核对，界面不得显示成功。
- 执行后验证失败：尝试补偿并升级人工处理。
- 用户取消：停止未开始工具，已执行操作按补偿能力处理。
