# 22 分级 Agent 记忆与持久上下文

## 1. 目标与边界

记忆不是第二套业务事实库。任务、项目、流程、会议、知识和人员信息仍以各自权威领域对象为准；记忆只保存经过权限过滤的工作线索、上下文快照和用户明确确认的稳定约束，帮助主 Agent 在跨轮、跨页面与交接后保持连续理解。

模型不能直接读写数据库。它只能通过 `enterprise-memory` Skill 的声明式 Tool 检索或提出长期记忆写入；权限、确认、RLS、留存和撤销由服务端执行。

## 2. 五级记忆

| 层级 | 内容 | 写入方式 | 默认留存 | 读取边界 |
|---|---|---|---|---|
| 对话记忆 `conversation` | 单轮用户—Agent 摘要 | 主对话完成后自动沉淀 | 30 天 | 仅会话所有者 |
| 上下文记忆 `context` | 某次运行使用的授权项目/任务/引用快照 | 主 Agent 自动沉淀 | 24 小时 | 当前会话或同一用户的同项目上下文 |
| 长期记忆 `long_term` | 用户明确确认的稳定偏好、事实或约束 | `memory.remember`，R2 人工确认 | 默认不自动过期 | 私有仅本人；共享需额外权限 |
| 任务记忆 `task` | 任务版本、状态、验收、证据、交接与文件引用快照 | 从可见任务/交接权威对象自动刷新 | 180 天 | 仅已通过任务领域可见性过滤的任务 |
| 情景记忆 `situational` | 项目当前健康度、风险、行动和可引用经营态势 | 主 Agent 自动沉淀 | 14 天 | 仅当前有权读取的项目范围 |

自动记忆一律标记来源、置信度和过期时间。它们不能替代当前领域对象，也不会自动升级为长期企业政策。

## 3. 存储、权限和审计

`0022_agent_memory.sql` 创建 `agent_memory_entries`：包含租户、层级、范围、所有者、可见性、数据分级、摘要、来源引用、来源对象、置信度、重要度、版本、到期时间和状态。表启用并强制 RLS，插入、更新、失效均写入原子摘要审计。

- `memory:read`：读取本人长期记忆。
- `memory:write`：声明私有长期记忆。
- `memory:read_shared`：读取当前授权范围内的共享长期记忆。
- `memory:share`：提出项目/企业共享长期记忆。
- `memory:manage`：使他人记忆失效，仅限受控治理角色。

失效不物理删除记录，而是以版本 compare-and-set 标为 `expired`；审计链保持可核验。一次性指令、未经验证的推断、密码/Token、健康信息、薪酬、绩效标签及不必要的敏感个人数据禁止写入长期记忆。

## 4. 检索与上下文构建

每次主 Agent 运行按当前身份和业务范围构造记忆候选：私有对话/上下文、已授权任务与交接、当前项目情景、以及具有共享读取权限的长期记忆。候选先经过范围过滤和到期过滤，再按查询匹配、重要度、置信度和时效排序，最多注入 12 条，并放入 `<untrusted_memory_context>`。

记忆引用随 Agent Run 持久化，最终答复可显示其类型与版本。记忆正文、用户文本、工具结果和知识检索结果都属于不可信数据，不能改变系统规则、权限、确认或 Tool 策略。

## 5. Tool 与 HTTP 契约

| 能力 | Tool / API | 风险与约束 |
|---|---|---|
| 检索长期记忆 | `memory.recall` / `GET /api/v1/memory` | R0；只返回当前主体可读范围 |
| 写入长期记忆 | `memory.remember` / `POST /api/v1/memory` | Agent 路径 R2 人工确认；共享范围另验 `memory:share` |
| 使记忆失效 | `DELETE /api/v1/memory/{id}` | 带 `version` 的 CAS；本人或 `memory:manage` |

网页直接调用写入 API 时，请求体本身是已认证用户的明确保存意图；主对话经由 Agent 写入时必须先形成不可篡改确认提案。两条路径都执行相同的权限、范围、分类、留存和审计检查。

## 6. 与统一办公路由的关系

`enterprise-memory` 是主对话的基础 Skill，而不是任务模块的附属功能。除任务与沟通外，主 Agent 还通过只读 Tool 访问企业治理、经营智能、知识、会议和流程预审；正式变更继续留在相应业务模块和确认门禁内。这样主对话负责理解、检索、编排和提出可确认动作，各领域模块仍保持唯一事实源。
